# План реализации копии главной страницы growth.tlb.org

## 1. Что мы увидели через Playwright
- Главная визуализация — один `<canvas>` на всю область графика.
- Вся интерактивность нарисована на canvas: кнопки, подписи, подсказки и ручки перетаскивания.
- Управление:
  - Красные и зеленые “ручки” для изменения начальных значений расходов/выручки и роста выручки.
  - Клик по надписи `change` переключает единицы времени: `week → month → quarter → year → week`.
- График показывает:
  - Линии расхода (красная) и выручки (зеленая).
  - Синюю заливку между кривыми как объем необходимого капитала.
  - Точку безубыточности с подписью.
  - Метку “$1B/yr revenue” на линии выручки.
  - Логарифмическую шкалу по оси Y.
  - Подпись “Profitable at …” рассчитывается по пересечению экспонент.

## 2. Цели копирования функциональности
- 1:1 логика расчета и визуального поведения графика.
- Идентичные пользовательские взаимодействия (перетаскивание, ховеры, клики).
- Сохранение вычислений роста/капитала и форматирования значений.
 - Совпадение с оригиналом по округлениям, шагам шкал и форматированию подписей.

## 3. Архитектура будущей реализации
- Модуль модели (например, `src/model/GrowthModel.ts`):
  - Параметры: `units`, `rev0`, `revGrowth`, `exp0`, `expGrowth`, `nWeeks`, `minFlow`, `maxFlow`.
  - Формулы расчета лог‑роста, капитала и точки безубыточности.
  - Методы `setRevAtWeek`, `setExpAtWeek`, `toggleUnits`, `calc`.
  - Производные поля:
    - `rev0Log = log(rev0)`, `exp0Log = log(exp0)`.
    - `revLogGrowth = log(1 + revGrowth)`, `expLogGrowth = log(1 + expGrowth)`.
    - `revN = revAtWeek(nWeeks)`, `expN = expAtWeek(nWeeks)`.
    - `ipoWeek` — момент, когда выручка достигнет `$1B/год`.
- Модуль рендера (например, `src/canvas/GrowthRenderer.ts`):
  - Преобразования координат `week ↔ x`, `flow ↔ y` (log scale).
  - Рисование линий, заливки, подписей, сетки, подсказок.
- Модуль взаимодействий (например, `src/canvas/HitDetector.ts`):
  - Слои интерактивных областей.
  - Drag/hover/click обработчики.
- UI‑обертка (React или чистый JS):
  - Инициализация canvas, resize, devicePixelRatio.

## 4. Библиотеки и технологии
- Стек: чистый Vanilla JS без сторонних библиотек.
- Рендер: Canvas 2D, полностью кастомный.
- Для Webflow: один внешний `bundle.js` + контейнер в Embed.
 - Стилистика: tailwind-like (утилитарные классы), но без подключения Tailwind.
- Вспомогательные утилиты:
  - Форматирование денежных величин и процентов.
  - Конвертация единиц времени (week/month/quarter/year).

## 5. Пошаговый план работ
1. Согласовать структуру папок и способ сборки (локальная сборка в один `bundle.js`).
2. Реализовать математическую модель роста и расчет ключевых метрик.
   - Формула точки безубыточности:
     - Если `exp0 <= rev0`, то `breakevenWeek = 0`.
     - Иначе:  
       `breakevenWeek = (log(exp0) - log(rev0)) / (log(1 + revGrowth) - log(1 + expGrowth))`
   - `breakevenFlow = revAtWeek(breakevenWeek)`.
   - Подпись “Profitable at …” форматируется через выбранные единицы времени.
   - Капитал до безубыточности:
     - Интеграл разницы расходов и выручки:
       - `totalExp = exp0 * (expLogGrowth === 0 ? t : (exp(expLogGrowth * t) - 1) / expLogGrowth)`
       - `totalRev = rev0 * (revLogGrowth === 0 ? t : (exp(revLogGrowth * t) - 1) / revLogGrowth)`
       - `capitalNeeded = totalExp - totalRev`
     - Если `exp0 <= rev0`, то `capitalNeeded = 0`.
   - `$1B/yr revenue`:
     - Внутренний расчет идет в неделях, поэтому целевая точка:
       - `targetWeekly = 1e9 / 52`
       - `ipoWeek = (log(targetWeekly) - rev0Log) / revLogGrowth`
     - Метка рисуется, если `ipoWeek` в разумном диапазоне (как в оригинале).
3. Реализовать функции форматирования чисел, процентов и подписей осей.
   - Формат денег:
     - `>= 1e12` → суффикс `T`
     - `>= 1e9` → `B`
     - `>= 1e6` → `M`
     - `>= 1e3` → `k`
     - Динамическое количество знаков после запятой, зависящее от масштаба.
   - Формат процентов:
     - `A(e)` → `e * 100`, число знаков зависит от масштаба.
     - Функция `R` пересчитывает рост под единицы времени:
       - `week` → как есть
       - `month` → `(1 + e)^(d) - 1`
       - `quarter` → `(1 + e)^(v) - 1`
       - `year` → `(1 + e)^(c) - 1`
   - Формат подписей времени:
     - `week X`, `month X`, `QX`, `year X`.
4. Реализовать рендер:
   - Оси, подписи, сетка, заливка капитала.
   - Линии расхода/выручки.
   - Точки безубыточности и $1B/yr маркер.
   - Детали координат:
     - `week → x`: линейная шкала на [0, nWeeks].
     - `flow → y`: лог‑шкала между `minFlow` и `maxFlow`.
   - Лейблы осей:
     - Горизонтальные метки годов с шагом 1 год.
     - Вертикальные метки по заранее заданному списку значений (как в оригинале).
   - Заливка капитала:
     - Градиент от `rgba(200,200,255,0.3)` к `rgba(200,200,255,0.9)`.
   - Ручки (drag handles):
     - Красные для расходов, зеленые для выручки.
     - Рисуются как круги с градиентной заливкой и обводкой.
5. Реализовать интерактивные элементы:
   - Drag‑ручки для `rev0`, `exp0`, `revGrowth`.
   - Нижние инпуты, синхронизированные с ручками (изменение значения обновляет график и наоборот).
   - Инпут `Gross Margin` присутствует в UI, но не влияет на расчет (на этом этапе).
   - Переключение `units` через radio‑buttons: `weekly | monthly | quarterly | yearly`.
   - Подсказки при ховере.
   - Форматы инпутов:
     - `Revenue`, `Fixed Expenses` — суммы за выбранную единицу времени.
     - `Growth Rate`, `Gross Margin` — проценты за выбранную единицу времени.
   - При смене `units` выполняется пересчет и ресинк значений инпутов и ручек.
   - Механика drag:
     - `rev0`/`exp0` меняются через `setRevAtWeek(0, value)` и `setExpAtWeek(0, value)`.
     - `revGrowth` задается перетаскиванием второй зеленой ручки:
       - `setRevAtWeek(week, value)` вычисляет рост из новой точки.
   - Radio‑buttons изменяют `units` напрямую (без циклического переключения).
6. Добавить адаптивность и корректный `devicePixelRatio`.
7. Визуально сверить с оригиналом и довести до 1:1 поведения.
8. Подготовить Webflow‑встраивание:
   - HTML‑контейнер для Embed (например, `<div id="growth-calc"></div>`).
   - Подключение внешнего `bundle.js` через `<script src=\"...\"></script>`.

## 6. Риски и уточнения
- В оригинале поведение определяется minified JS, поэтому нужна верификация тонких деталей (шаги сетки, округления, оттенки).
- Вся логика “кнопок” реализована как графика на canvas, без DOM‑элементов.
- Встроенный canvas должен уважать размеры контейнера Webflow и ресайзиться при изменении ширины.
 - На первом этапе визуал (цвета/шрифты/отступы) повторяет оригинал один-в-один.
